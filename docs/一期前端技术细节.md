# 第一期前端技术细节

## 1. 一期前端目标

第一期前端需要完成以下能力：

1. 用户进入系统后自动获得临时身份
2. 首页支持创建表格并进入表格
3. 表格页支持通过分享链接进入指定文档
4. 表格页支持导入 Excel
5. 表格页支持查看和编辑单元格文本
6. 多个客户端可通过 WebSocket 实时同步修改
7. 页面展示当前在线用户

## 2. 技术选型

结合赛题建议与当前仓库结构，一期前端建议采用以下技术栈：

- 框架：React
- 构建工具：Vite
- 语言：TypeScript
- 路由：React Router
- 状态管理：Zustand
- Excel 解析：`xlsx`
- 协同通信：原生 WebSocket
- 样式方案：基础 CSS 或 CSS Modules

说明：

- `课题.md` 推荐 `React + Vite + TypeScript`，与当前项目方向一致
- 状态管理优先选择轻量方案，便于一期快速落地
- WebSocket 客户端先保持简单，不引入额外协议层库

## 3. 一期页面设计

### 3.1 首页 `/`

首页用于完成“进入系统 -> 创建表格 -> 进入表格”链路。

建议页面包含以下区域：

- 顶部用户信息区：展示临时身份昵称和颜色
- 创建表格按钮：点击后调用 `POST /docs`

首页前端职责：

- 初始化临时身份
- 创建新文档后跳转
- 处理创建中的加载态和错误态

### 3.2 表格详情页 `/sheet/:docId`

表格页用于完成“加入房间 -> 获取快照 -> 查看表格 -> 编辑 -> 协同同步 -> 导入 Excel -> 分享链接”链路。

建议页面包含以下区域：

- 顶部栏：显示文档标题或 `docId`
- 在线用户区：显示当前房间在线用户
- 操作区：导入 Excel、复制分享链接
- 表格区域：渲染表格内容并支持单元格编辑

表格页前端职责：

- 读取 `docId`
- 建立 WebSocket 连接并发送 `join`
- 保存当前文档 `snapshot`
- 渲染表格
- 发送编辑消息
- 接收协同广播并更新本地状态

## 4. 前端模块拆分

### 4.1 身份模块

职责：

- 首次进入时生成临时身份
- 从 `sessionStorage` 读取已有身份
- 将身份信息传给首页和表格页

推荐数据结构：

```ts
type SessionUser = {
  clientId: string;
  name: string;
  color: string;
};
```

实现建议：

- `clientId` 使用 `crypto.randomUUID()`
- `name` 使用简单规则生成，如 `用户1234`
- `color` 从固定颜色池中随机挑选
- 身份保存在 `sessionStorage`

说明：

- 这里的会话范围是浏览器标签页或浏览器窗口
- 同一个标签页内从首页跳转到表格页时身份不失效
- 关闭当前标签页或窗口后身份失效

### 4.2 路由模块

一期建议只保留两条主路由：

- `/`：首页
- `/sheet/:docId`：表格详情页

可选增强：

- 增加 `NotFound` 页面
- 增加表格页连接失败或文档不存在时的兜底页

### 4.3 API 模块

HTTP 部分只需要覆盖一期最小能力：

- `GET /health`
- `POST /docs`

前端 API 模块职责：

- 统一封装基础请求
- 统一处理加载态和错误态
- 对接口返回值做类型约束

一期前端对 HTTP 响应统一按以下结构解析：

```ts
type ApiResponse<T> = {
  code: number;
  message: string;
  data: T;
};
```

约定：

- `code === 0` 表示成功
- 非 `0` 表示失败
- 页面层优先读取 `message` 作为错误提示

### 4.4 WebSocket 协同模块

一期协同链路围绕以下事件展开：

- `join`
- `set_cell`
- `import_sheet`
- `presence`

WebSocket 模块职责：

- 创建连接
- 加入房间
- 发送编辑事件
- 发送导入事件
- 接收广播事件
- 接收在线用户事件
- 在页面卸载时关闭连接

建议将 WebSocket 封装为单独模块，而不是把连接逻辑散落在组件内部。

一期前端对 WebSocket 消息统一按以下结构解析：

```ts
type WsMessage<T> = {
  type: string;
  code: number;
  message: string;
  data: T;
};
```

前端处理顺序建议为：

1. 先判断 `type`
2. 再判断 `code`
3. 成功时读取 `data`
4. 失败时读取 `message`

### 4.5 表格状态模块

一期虽然功能不多，但建议尽早统一表格数据结构，以便后续迁移到 Canvas 渲染和 undo/redo。

推荐结构：

```ts
type Cell = {
  value: string;
};

type SheetSnapshot = {
  cells: Record<string, Cell>;
  styles: Record<string, unknown>;
  rowCount: number;
  colCount: number;
};

type SheetStore = {
  docId: string | null;
  snapshot: SheetSnapshot | null;
  selectedCell: { row: number; col: number } | null;
  users: SessionUser[];
  setSnapshot: (snapshot: SheetSnapshot) => void;
  setSelectedCell: (cell: { row: number; col: number } | null) => void;
  updateCellValue: (row: number, col: number, value: string) => void;
  setUsers: (users: SessionUser[]) => void;
};
```

### 4.6 表格渲染模块

一期可以先以“基础二维表格渲染”为主，但数据模型和交互接口要为后续 Canvas 做准备。

这里建议采用两层思路：

- 一期落地层：先用 DOM 表格或简化网格渲染，快速打通业务链路
- 后续演进层：逐步替换为 Canvas 渲染

这样做的原因：

- 一期的核心风险在业务链路和协同，不在性能极限
- 赛题最终要求是 Canvas，但可以先把数据流、选中态、编辑态和协同打通
- 后续改渲染层时，尽量不改身份、路由、协同和数据结构

一期表格区域需要支持：

- 根据 `snapshot` 渲染可见单元格
- 点击单元格时更新选中状态
- 显示当前选中单元格的边框或高亮态
- 双击或回车进入编辑态

## 5. Canvas 方向预埋

虽然一期可以先不把渲染层完全做成 Canvas，但前端技术设计必须向赛题要求靠拢。

根据 `课题.md`，后续前端会拆成四层：

1. Data Model
2. Render Engine
3. Interaction
4. Collab

一期前端建议先把这个分层意识体现在目录和模块设计里。

### 5.1 Data Model

负责：

- 单元格值
- 行列规模
- 样式占位
- 选中单元格
- 历史版本或快照数据

重点要求：

- 单元格采用稀疏存储
- key 使用 `row:col` 形式，例如 `1:1`
- 即使一期不做复杂样式，也保留 `styles` 字段

### 5.2 Render Layer

一期职责：

- 根据 `snapshot` 渲染当前表格
- 管理选中态的视觉反馈
- 控制编辑态入口

后续向 Canvas 迁移时要保留的接口：

- `render(snapshot, viewport)`
- `highlightCell(cell)`
- `startEdit(cell)`

### 5.3 Interaction Layer

负责：

- 选中单元格
- 双击进入编辑
- 回车提交
- ESC 取消
- 未来支持方向键、Tab 和批量选区

一期建议先实现：

- 单击选中
- 双击编辑
- Enter 提交
- Blur 提交

### 5.4 Collab Layer

负责：

- 将本地编辑转换成协议消息
- 将服务端广播结果合并进本地状态
- 维护在线用户列表
- 维护 `seq` 与历史快照

## 6. Excel 导入设计

根据 `课题.md`，一期推荐将 Excel 解析放在前端，用 `SheetJS` 解析后再转换为内部结构。

流程建议如下：

1. 用户选择本地 `.xlsx` 文件
2. 前端读取文件内容
3. 使用 `xlsx` 解析工作簿
4. 只读取第一个工作表
5. 遍历单元格数据并转换成 `SheetSnapshot`
6. 通过 WebSocket 发送 `import_sheet`
7. 服务端广播导入后的最新快照
8. 前端收到广播后更新表格视图

一期简化策略：

- 只导入值，不导入 Excel 样式
- 数字和日期先按字符串展示
- 不处理多 Sheet

前端需要处理的异常：

- 文件类型不支持
- 文件内容为空
- 解析失败
- 导入过程中连接已断开

## 7. 单元格编辑设计

根据课题要求，最终需要支持可编辑输入和中文输入法。第一期可以先实现简化版文本编辑，但要为后续 Canvas 输入层预留思路。

一期建议：

- 先实现单元格双击进入编辑态
- 编辑态使用 DOM 输入控件
- 提交后更新本地状态并发送 `set_cell`

推荐流程：

1. 用户双击某个单元格
2. 页面进入编辑态
3. 用户输入文本
4. 用户按 Enter 或失焦时提交
5. 前端先更新本地状态
6. 前端通过 WebSocket 发送 `set_cell`
7. 服务端广播结果后再次对齐

后续迁移到 Canvas 时，编辑区建议采用赛题中提到的 DOM overlay 方案：

- Canvas 负责显示
- `textarea` 或 `contenteditable` 负责输入

## 8. 协同与状态同步

### 8.1 一期协同策略

一期采用中心化房间协同模型：

- 客户端进入文档房间
- 服务端返回当前 `snapshot`
- 前端在本地渲染当前文档
- 本地编辑通过 WebSocket 发给服务端
- 服务端顺序处理并广播
- 所有客户端按服务端广播结果收敛到同一状态

### 8.2 `seq` 的前端意义

虽然 `seq` 是服务端生成的，但前端需要理解它的用途：

- 标记服务端确认顺序
- 帮助后续 `undo/redo` 对齐历史记录
- 让调试时可以知道当前文档处于第几次修改之后

一期前端可以先做到：

- 接收并保存 `seq`
- 在收到广播时同步更新本地最新 `seq`
- 不在客户端实现复杂补偿逻辑

### 8.3 历史快照的前端用途

一期文档已经约定服务端保留有限历史快照，为后续 `undo/redo` 铺垫。前端侧也建议同步保留一份轻量历史信息，用于未来扩展。

一期前端可选做法：

- 保存最近一次服务端确认的 `seq`
- 保存最近一次 `snapshot`
- 为后续接入 `undo/redo` 预留 store 字段

## 10. 一期交互与异常处理

前端至少要覆盖以下状态：

- 创建文档失败
- 表格页连接中
- 表格页连接失败
- Excel 解析失败
- 文档不存在或加入失败

建议每个页面至少具备：

- 加载态
- 错误态

## 11. 一期验收视角

从前端视角看，一期完成的标准至少包括：

- 打开首页后自动生成临时身份
- 可以在首页创建表格
- 可以进入指定表格页
- 可以复制分享链接
- 可以导入 Excel 并看到内容
- 可以编辑单元格文本
- 两个页面可实时同步文本修改
- 可以看到在线用户

## 12. 二期演进方向

第一期前端完成后，建议按以下顺序继续演进：

1. 将表格渲染层替换为 Canvas
2. 增加 DOM overlay 输入层，完善中文输入法体验
3. 增加工具栏和样式系统
4. 接入 undo/redo
5. 增加增删行列
6. 优化虚拟滚动和性能

## 13. 一期结论

第一期前端的核心不是一次性做完完整表格编辑器，而是先把以下主链路做稳定：

- 临时身份
- 创建文档
- 进入表格
- 导入 Excel
- 编辑单元格
- WebSocket 协同同步

在这个基础上，前端的数据结构、模块边界和交互方式要尽量向赛题要求靠拢，为后续 Canvas、undo/redo、样式工具栏和复杂协同保留演进空间。
