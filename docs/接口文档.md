## 通用约定

#### HTTP

- 有请求体的请求需携带 Content-Type: application/json 请求头（GET 请求无需携带）。
- HTTP 状态码遵循标准语义：200 成功、201 创建成功、400 参数错误、404 资源不存在、500 服务器错误。
- 正常路由处理的响应体统一为以下 JSON 结构。例外：若请求携带了格式非法的 JSON 正文（无法解析），Express 内置的 body-parser 会在路由执行前直接返回 `400 text/html` 错误页，不经过业务逻辑，也不符合此统一结构。

```json
{
  "code": 0,
  "message": "ok",
  "data": { }
}
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| code | number | 业务码，0 表示成功，非零表示错误 |
| message | string | 说明文字，成功时为 "ok"，错误时为具体描述 |
| data | object \| null | 业务数据，错误时为 null |

> 发送格式非法的 JSON 正文（如 `POST /docs` 请求体不是合法 JSON），服务端返回 `400 text/html` Express 错误页，而非上述 JSON 结构。前端应避免发送格式破损的请求体。

#### WebSocket

- 所有消息均为 JSON 字符串，必须包含 type 字段。
- 服务端响应同样包含 type、code、message、data 字段。
- 单条消息最大负载为 1 MB（由 `WS_MAX_PAYLOAD_BYTES` 环境变量控制）。

## 业务码对照表

| 业务码 | 对应 HTTP 状态码 | 含义 |
| --- | --- | --- |
| 0 | 200 / 201 | 成功 |
| 4000 | 400 | 参数错误 / 业务规则不满足 |
| 4001 | 400 | 不支持的消息类型（WebSocket 专用） |
| 4003 | 403 | 无权限（WebSocket 专用，如未 join 直接调用需要房间成员资格的接口） |
| 4004 | 404 | 文档不存在 |
| 4090 | 409 | 版本冲突 / 需要刷新后重试 |
| 5000 | 500 | 服务器内部错误 |

### POST /docs — 创建文档

创建一个新的在线文档，返回文档初始状态（含空快照）。

支持通过 eventId 实现幂等控制：携带相同 eventId 的重试请求直接返回首次结果，不重复创建文档。

#### 完整请求示例

```http
POST http://localhost:3000/docs
Content-Type: application/json
```

```json
{
  "title": "季度报表",
  "createdBy": "user_001",
  "eventId": "evt_create_doc_001"
}
```

#### 请求体字段

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| title | string | 否 | 文档标题；不传时默认 "Untitled"；不可为纯空白字符串；非字符串返回 4000 |
| `createdBy` | string | 否 | 创建人标识；不传或传 `null` 时记录为 `null`；不可为空字符串或纯空白字符串；非字符串返回 `4000` |
| eventId | string | 否 | 幂等键；不传或传 null 时不做幂等控制；不可为纯空白字符串；非字符串返回 4000 |

#### 响应 — HTTP `201`

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "docId": "doc_001",
    "title": "季度报表",
    "currentSeq": 0,
    "createdBy": "user_001",
    "createdAt": "2026-05-27T10:00:00.000Z",
    "updatedAt": "2026-05-27T10:00:00.000Z",
    "snapshot": {
      "activeSheetId": "sheet_doc_001_001",
      "sheetOrder": ["sheet_doc_001_001"],
      "sheets": {
        "sheet_doc_001_001": {
          "id": "sheet_doc_001_001",
          "name": "Sheet1",
          "defaultRowHeight": 25,
          "defaultColWidth": 100,
          "rowCount": 0,
          "colCount": 0,
          "styles": {},
          "cells": {}
        }
      }
    }
  }
}
```

**响应 `data` 字段说明**

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| docId | string | 文档唯一 ID，格式 doc_xxx，自动分配，从 doc_001 起（种子数据 doc_sys_001 使用固定 ID 直接插入，不占用自增计数器） |
| title | string | 文档标题 |
| currentSeq | number | 当前操作序列号，新建文档初始为 0 |
| createdBy | string \| null | 创建人 |
| createdAt | string | 创建时间，ISO 8601 格式 |
| updatedAt | string | 最后更新时间，ISO 8601 格式 |
| snapshot | object | 文档快照，当前为 workbook 结构，见[快照结构](#快照结构) |

#### 错误响应示例

title 为纯空白字符串 — HTTP 400：

```json
{
  "code": 4000,
  "message": "title must be a non-empty string",
  "data": null
}
```

```json

  "code": 4000,
  "message": "createdBy must be a non-empty string",
  "data": null
}
```

createdBy 类型不是字符串（如传数字）— HTTP 400：

```json
{
  "code": 4000,
  "message": "createdBy must be a string",
  "data": null
}
```

eventId 为纯空白字符串 — HTTP 400：

```json
{
  "code": 4000,
  "message": "eventId must be a non-empty string",
  "data": null
}
```

title 类型不是字符串（如传数字）— HTTP 400：

```json
{
  "code": 4000,
  "message": "title must be a string",
  "data": null
}
```

```json
{
  "code": 4000,
  "message": "request body must be an object",
  "data": null
```

### GET /docs — 查询文档列表

按用户和范围分页查询文档列表，结果按 updatedAt 倒序排列（时间相同时再按 docId 倒序）。

#### 完整请求示例

```http
GET http://localhost:3000/docs?userId=user_001&scope=all&page=1&pageSize=20
```

#### Query 参数

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| userId | string | 是 | 用户 ID，不可为空 |
| scope | string | 是 | 查询范围：created（我创建的）、participated（我参与的）、all（两者合集） |
| page | number | 是 | 页码，正整数，从 1 开始 |
| pageSize | number | 是 | 每页条数，正整数，最大 100；也兼容写作 pagesize（小写） |

**`scope` 说明**

- created：返回 createdBy === userId 的文档。
- participated：返回该用户通过 WebSocket join 加入过（有 roomUser 记录）、且不是自己创建的文档。
- all：合并以上两类，同一文档只出现一次，relation 优先标记为 "created"。

#### 响应 — HTTP `200`

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "list": [
      {
        "docId": "doc_003",
        "title": "协作文档",
        "createdBy": "user_002",
        "createdAt": "2026-05-27T09:00:00.000Z",
        "updatedAt": "2026-05-27T11:00:00.000Z",
        "currentSeq": 5,
        "relation": "participated"
      },
      {
        "docId": "doc_002",
        "title": "季度报表",
        "createdBy": "user_001",
        "createdAt": "2026-05-27T10:00:00.000Z",
        "updatedAt": "2026-05-27T10:30:00.000Z",
        "currentSeq": 2,
        "relation": "created"
      }
    ],
    "page": 1,
    "pageSize": 20,
    "total": 2,
    "hasMore": false
  }
}
```

**响应 `data` 字段说明**

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| list | array | 当前页文档列表 |
| list[].docId | string | 文档 ID |
| list[].title | string | 文档标题 |
| list[].createdBy | string \| null | 创建人 |
| list[].createdAt | string | 创建时间 |
| list[].updatedAt | string | 最后更新时间 |
| list[].currentSeq | number | 当前序列号 |
| list[].relation | string | 与查询用户的关系："created" 或 "participated" |
| page | number | 当前页码 |
| pageSize | number | 每页条数 |
| total | number | 符合条件的文档总数 |
| hasMore | boolean | 是否还有下一页 |

#### 错误响应示例

userId 为空 — HTTP 400：

```json
{
  "code": 4000,
  "message": "userId must be a non-empty string",
  "data": null
}
```

```json
{
  "code": 4000,
  "message": "scope must be one of: created, participated, all",
  "data": null
}
```

```json
{
  "code": 4000,
  "message": "page must be a positive integer",
  "data": null
}
```


## WebSocket 接口

### 连接说明

```http
ws://localhost:3000
```

- 建立连接后即可发送消息，无需鉴权握手。
- 每条消息都是一个 JSON 字符串，必须包含 type 字段。
- 客户端断开连接时，服务端自动将其从房间移除，并向房间内其余客户端广播更新后的在线用户列表（presence）。
- 同一 clientId 可以建立多个 socket 连接；只有该 clientId 的最后一个连接断开时，才会触发广播。
- **`join` 与写操作的关系**：当前实现中 `set_cell`、`insert_row`、`delete_row`、`insert_col`、`delete_col`、`set_title`、`add_sheet`、`undo`、`redo` 都要求发送方已通过 `join` 进入目标文档，且当前 socket 绑定的 `clientId` 必须与消息中的 `clientId` 一致，否则返回 `4003`。同一 socket 切换到其他文档后，旧文档上的这些操作也会失效。`import_sheet` 仍不要求发送方先 `join`；未加入房间的 socket 也可以直接执行导入并收到响应。所有写操作的广播仍只会发送给已在房间内的客户端。

### 消息通用格式

#### 客户端 → 服务端

```json
{
  "type": "消息类型",
  "...": "其他字段"
}
```

#### 服务端 → 客户端（成功）

```json
{
  "type": "响应类型",
  "code": 0,
  "message": "ok",
  "data": { }
}
```

#### 服务端 → 客户端（错误）

```json
{
  "type": "error",
  "code": 4000,
  "message": "错误描述",
  "data": null
}
```

### join — 加入文档房间

加入指定文档的协作房间。

成功后：
- 向当前客户端返回 `join_ack`，包含文档快照和当前在线用户列表。
- 若该 `clientId` 之前不在线，向房间内所有客户端（含自己）广播 `presence`。
- 若该 clientId 已有其他连接在线，则不广播 presence。

**提交后失败策略**：当前实现以 `joinRoom()` 成功作为 join 已提交的边界。一旦加入房间成功，后续在线列表查询、`presence` 广播或审计日志写入即使失败，也不会把本次 `join` 反向改成 `error`；客户端仍以已收到的 `join_ack` 为准。

**并发重复 join（同一连接、同一 docId + clientId）**：若同一 socket 在首条 join 尚未完成时发出第二条相同 join，第二条会等待首条完成并重放相同响应（`join_ack` 或 error），不会触发第二次 `joinRoom` 也不会产生额外 `presence` 广播。

#### 完整发送示例

```json
{
  "type": "join",
  "docId": "doc_sys_001",
  "clientId": "user_001",
  "name": "Alice",
  "color": "#ff0000"
}
```

#### 发送字段

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| type | string | 是 | 固定值 "join" |
| docId | string | 是 | 要加入的文档 ID，必须是非空字符串，否则返回 4000 |
| clientId | string | 是 | 客户端/用户唯一标识，必须是非空字符串，否则返回 4000 |
| name | string | 否 | 显示名称；不传或非字符串时均回退为 ""，不做格式校验 |
| color | string | 否 | 用户标识色；不传、空字符串或非字符串时均回退为 "#3b82f6"，不校验颜色格式 |

### set_cell — 更新单元格

更新文档中指定单元格的值和样式。操作成功后：
- 先通过 `reply` 向发送方返回 `cell_updated`，再通过 `broadcastToRoom` 向房间内所有客户端（含发送方）广播同一条消息。**发送方会收到 2 条相同的 `cell_updated`**，其他客户端收到 1 条。
- 将本次操作写入操作历史（historyStore）。
- 将本次操作压入当前用户的 undo 栈，并清空 redo 栈。
- 若携带 `baseSeq`，服务端会基于 `(baseSeq, currentSeq]` 历史执行最小 rebase；`import_sheet` 被视为 barrier，需刷新后重试。

> **需要先 join**：发送方必须已通过 `join` 加入目标文档，且当前 socket 绑定的 `clientId` 必须与消息中的 `clientId` 一致，否则返回 `4003`。
>
> `style` 为全量替换：每次调用需传入该单元格完整的 style 对象，不做字段合并。

#### 完整发送示例

```json
{
  "type": "set_cell",
  "docId": "doc_sys_001",
  "clientId": "user_001",
  "sheetId": "sheet_20260527_001",
  "row": 1,
  "col": 1,
  "value": "姓名",
  "style": {
    "bold": true,
    "fontSize": 14,
    "color": "#333333"
  }
}
```

#### 带 `baseSeq` 的发送示例

```json
{
  "type": "set_cell",
  "docId": "doc_sys_001",
  "clientId": "user_001",
  "sheetId": "sheet_20260527_001",
  "row": 1,
  "col": 1,
  "value": "姓名",
  "style": {
    "bold": true,
    "fontSize": 14,
    "color": "#333333"
  },
  "baseSeq": 12
}
```

#### 发送字段

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| type | string | 是 | 固定值 "set_cell" |
| docId | string | 是 | 文档 ID，必须是非空字符串，否则返回 4000 |
| clientId | string | 是 | 操作用户 ID，必须是非空字符串，否则返回 4000 |
| `sheetId` | string | 是 | 目标工作表 ID，必须是非空字符串，否则返回 4000 |
| row | number | 是 | 行号，正整数，从 1 开始 |
| col | number | 是 | 列号，正整数，从 1 开始 |
| `value` | string | 否 | 单元格文本值；不传时视为 `""`。当前不做类型校验，非字符串值会被原样存储并广播 |
| `style` | object | 否 | 单元格样式；不传时视为 `null`（清空样式）。当前不做类型校验，非对象值会被原样存储并广播 |
| `baseSeq` | number | 否 | 客户端发起本次写入时所见的文档级全局 seq；必须是大于等于 0 的整数。旧客户端可不传，不传时按非 OT 请求处理 |

**`style` 字段说明**

后端对 `style` 对象不做白名单校验，任何字段均会原样存储并广播给房间内其他客户端。以下是前端约定使用的字段：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| bold | boolean | 是否加粗 |
| italic | boolean | 是否斜体 |
| underline | boolean | 是否下划线 |
| fontSize | number | 字体大小（px） |
| align | string | 对齐方式："left" / "center" / "right" |
| color | string | 字体颜色，如 "#ff0000" |
| backgroundColor | string | 背景颜色，如 "#ffffff" |

> `set_cell.style` 不做字段名规范化。也就是说，请求里传入的字段会原样保留；而 `snapshot.styles` 中常见的 `bgColor`、`hAlign` 等命名只是当前种子数据和导入快照里的常见写法，并不是后端强制规范。

**`baseSeq` 说明**

- `baseSeq` 表示客户端发起本次写入时，自己看到的该文档最新全局 `seq`。
- 不携带 `baseSeq` 时，请求依然合法，服务端按兼容旧客户端模式处理，不做显式基线校验。
- 携带 `baseSeq` 时，服务端会拿它和当前真实 `currentSeq` 比较：
- `baseSeq === currentSeq`：说明客户端基于最新版本发起写入，不需要重放。
- `baseSeq < currentSeq`：说明客户端基于旧版本发起写入，服务端会尝试在最新文档状态上继续重放。
- `baseSeq > currentSeq`：返回 `4090`。

**响应 — `cell_updated`（`broadcastToRoom` 广播给房间内所有客户端；发送方额外通过 `reply` 多收 1 条，共收到 2 条）**

```json
{
  "type": "cell_updated",
  "code": 0,
  "message": "ok",
  "data": {
    "docId": "doc_sys_001",
    "clientId": "user_001",
    "sheetId": "sheet_20260527_001",
    "seq": 1,
    "row": 1,
    "col": 1,
    "value": "姓名",
    "style": {
      "bold": true,
      "fontSize": 14,
      "color": "#333333"
    },
    "canUndo": true,
    "canRedo": false
  }
}
```

**响应 `data` 字段说明**

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| docId | string | 文档 ID |
| clientId | string | 操作用户 ID |
| `sheetId` | string | 实际写入的工作表 ID |
| seq | number | 本次操作的序列号，全文档单调递增 |
| row | number | 行号 |
| col | number | 列号 |
| value | string | 写入后的单元格值 |
| style | object \| null | 写入后的单元格样式 |
| canUndo | boolean | 操作后当前用户的 undo 栈是否非空（set_cell 后恒为 true） |
| canRedo | boolean | 操作后当前用户的 redo 栈是否非空（set_cell 后恒为 false，因为 redo 栈已被清空） |

#### 错误响应示例

缺少必填字段或 row/col 不是正整数：

```json
  "code": 4000,
  "message": "docId, clientId, sheetId, row and col are required",
```

### import_sheet — 整表导入

用传入的快照全量覆盖文档内容。操作成功后：
- 先通过 `reply` 向发送方返回 `sheet_imported`，再通过 `broadcastToRoom` 向房间内客户端广播同一条消息。
- 若发送方已 `join` 当前文档，**发送方会收到 2 条相同的 `sheet_imported`**，其他客户端收到 1 条。
- 若发送方未 `join` 当前文档，发送方只会收到 `reply` 的 1 条 `sheet_imported`；房间内其他已加入的客户端仍各收到 1 条广播。
- 将本次操作写入操作历史（historyStore）。
- 清空当前用户的 undo 栈和 redo 栈。
- 当前实现不要求发送方先 `join`，未加入房间的 socket 也可以直接执行导入并收到响应。
- 当前实现不使用 `baseSeq`。`import_sheet` 本身不做 OT 重放，而是作为后续 stale `set_cell` / `undo` / `redo` 的 barrier。
- 当前实现不做幂等控制；重复发送会重复执行整表覆盖，并继续分配新的全局 `seq`。

> **OT barrier 说明**：一旦 `import_sheet` 成功提交，基于导入前旧版本发起的 `set_cell`，或引用导入前历史操作的 `undo` / `redo`，在服务端都会被视为跨 barrier 的旧请求，并返回 `4090`，提示刷新后重试。

### undo — 撤销操作

撤销当前用户在指定文档上最近一次可撤销操作（仅撤销自己的操作，不影响其他用户）。发送方必须已通过 `join` 加入该文档，且当前 socket 绑定的 `clientId` 必须与消息中的 `clientId` 一致；如果尚未 join、已切换到其他文档，或 socket 当前身份已不是该 `clientId`，都会返回 `4003`。操作成功后：
- 先通过 `reply` 向发送方返回 `undo_applied`，再通过 `broadcastToRoom` 向房间内所有客户端（含发送方）广播同一条消息。**发送方会收到 2 条相同的 `undo_applied`**，其他客户端收到 1 条。
- 写入操作历史（opType: `"undo"`，sourceSeq 指向被撤销的原始操作的 seq，分配新的文档级全局 seq）。
- 将被撤销的操作从 undo 栈弹出并压入 redo 栈（保存完整操作快照，供 redo 时直接执行）。
- `import_sheet` 会清空 undo 栈，之后无法执行 undo。
- 若 `sourceSeq` 之后同一单元格已被后续操作触碰，undo 不再覆盖最新值，响应中的 `value/style` 会保持当前最新状态。
- 若 `sourceSeq` 之后遇到 `import_sheet`，返回 `4090`，要求刷新后重试。

**提交后失败策略**：当前实现以底层单元格写入成功（`applySetCell()` 成功返回）作为 undo 已提交的边界。此后若 history、user-op-state、audit 或广播失败，服务端只记录内部错误，不会再补发 `500`，客户端仍以已收到的 `undo_applied` 为准。

#### 完整发送示例

```json
{
  "type": "undo",
  "docId": "doc_sys_001",
  "clientId": "user_001"
}
```

#### 发送字段

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| type | string | 是 | 固定值 "undo" |
| docId | string | 是 | 文档 ID，必须是非空字符串，否则返回 4000 |
| clientId | string | 是 | 操作用户 ID，必须是非空字符串，否则返回 4000 |

**响应 — `undo_applied`（`broadcastToRoom` 广播给房间内所有客户端；发送方额外通过 `reply` 多收 1 条，共收到 2 条）**

```json
{
  "type": "undo_applied",
```

### redo — 重做操作

重做当前用户最近一次被撤销的操作。发送方必须已通过 `join` 加入该文档，且当前 socket 绑定的 `clientId` 必须与消息中的 `clientId` 一致；如果尚未 join、已切换到其他文档，或 socket 当前身份已不是该 `clientId`，都会返回 `4003`。操作成功后：
- 先通过 `reply` 向发送方返回 `redo_applied`，再通过 `broadcastToRoom` 向房间内所有客户端（含发送方）广播同一条消息。**发送方会收到 2 条相同的 `redo_applied`**，其他客户端收到 1 条。
- 写入操作历史（opType: `"redo"`，sourceSeq 指向被重做的原始操作的 seq，分配新的文档级全局 seq）。
- 将被重做的操作从 redo 栈弹出并重新压入 undo 栈。
- 执行新的 `set_cell` 或 `import_sheet` 会清空 redo 栈，此后 redo 将返回 "nothing to redo"。
- 若 `sourceSeq` 之后同一单元格已被后续操作触碰，redo 不再覆盖最新值，响应中的 `value/style` 会保持当前最新状态。
- 若 `sourceSeq` 之后遇到 `import_sheet`，返回 `4090`，要求刷新后重试。

**提交后失败策略**：当前实现以底层单元格写入成功（`applySetCell()` 成功返回）作为 redo 已提交的边界。此后若 history、user-op-state、audit 或广播失败，服务端只记录内部错误，不会再补发 `500`，客户端仍以已收到的 `redo_applied` 为准。

#### 完整发送示例

```json
{
  "type": "redo",
  "docId": "doc_sys_001",
  "clientId": "user_001"
}
```

#### 发送字段

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| type | string | 是 | 固定值 "redo" |
| docId | string | 是 | 文档 ID，必须是非空字符串，否则返回 4000 |
| clientId | string | 是 | 操作用户 ID，必须是非空字符串，否则返回 4000 |

**响应 — `redo_applied`（`broadcastToRoom` 广播给房间内所有客户端；发送方额外通过 `reply` 多收 1 条，共收到 2 条）**

```json
{
  "type": "redo_applied",
  "code": 0,
  "message": "ok",
  "data": {
    "docId": "doc_sys_001",
    "clientId": "user_001",
    "sheetId": "sheet_20260527_001",
    "seq": 3,
    "row": 1,
    "col": 1,
    "value": "姓名",
    "style": { "bold": true },
    "canUndo": true,
    "canRedo": false
  }
}
```

**响应 `data` 字段说明**

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| docId | string | 文档 ID |
| clientId | string | 操作用户 ID |
| `sheetId` | string | 被重做操作所在的工作表 ID |
| seq | number | 本次 redo 操作分配的新序列号 |
| row | number | 被重做的单元格行号 |
| col | number | 被重做的单元格列号 |
| value | string | 重做后该单元格的值（即执行 set_cell 时的新值） |
| style | object \| null | 重做后该单元格的样式 |
| canUndo | boolean | 重做后 undo 栈是否有内容（执行完 redo 后恒为 true） |

### OT 字段补充说明

以下字段用于表达当前后端的“最小服务端 OT / rebase”语义。

#### `baseSeq`

- 含义：客户端发起一次写请求时，自己所见的文档最新全局 `seq`。
- 当前主要用于 `set_cell` 与 `set_title`。
- 是否必填：否。旧客户端可不传。
- 不传时：请求仍然执行，但服务端不会基于客户端提供的版本做显式基线判断。

#### `sourceSeq`

- 当前主要出现在 `undo` / `redo` 内部语义和历史记录里，不作为客户端请求或响应字段暴露。
- 含义：被 `undo` 或 `redo` 引用的那条原始历史操作的全局 `seq`。
- 它不是客户端传入字段，而是服务端在 `undoStack` / `redoStack` 与 `history` 中维护的引用。
- 在 `mysql` 驱动下，它会对应 `history.seq`；在 `memory` 驱动下也有相同含义。

#### `currentSeq`

- 含义：服务端当前真实文档状态的最新全局版本号。
- `GET /docs/:docId`、`join_ack`、以及各类写操作成功响应中返回的 `seq` / `currentSeq` 都属于这套全局递增版本体系。

> 补充：`set_cell` / `undo` / `redo` 请求参数里的 `row`、`col` 当前要求从 `1` 开始；而 `snapshot.cells` 中已有历史数据或导入数据的 key/row/col 可能出现从 `0` 开始的内容。文档中的这两个坐标体系反映的是当前实现现状。

#### 它们之间的关系

```text
baseSeq    = 客户端发请求时看到的版本
currentSeq = 服务端当前真实最新版本
sourceSeq  = undo/redo 想引用的历史原始操作版本
```

#### 不带 `baseSeq` 和带 `baseSeq` 的区别

- 不带 `baseSeq`：
- 兼容旧客户端。
- 服务端不做“你基于哪个版本发出的”显式判断。
- 行为上更接近直接按当前最新状态执行，效果通常可以理解为后写覆盖。

- 带 `baseSeq`：
- 进入当前这版最小服务端 OT / rebase 语义。
- 服务端会知道“这次请求是基于哪个旧版本发出来的”。
- 因此可以做 stale rebase、版本冲突判断，以及在部分场景下返回 `4090`。
