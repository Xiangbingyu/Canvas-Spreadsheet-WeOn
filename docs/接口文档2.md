## 通用约定

- 本文中的 6 个接口均为 WebSocket 消息，不提供 HTTP 版本。
- 行列插删 4 个接口和 `batch_set_cell` 接口都必须先通过 `join` 加入目标文档房间。
- 行列插删 4 个接口和 `batch_set_cell` 接口要求发送方当前 socket 绑定的 `clientId` 必须与消息中的 `clientId` 一致，否则返回 `4003`。
- 行列接口中的行列下标均为 `1-based`。
- 插入行列表示插入空白行列，不会自动创建新单元格。
- 删除行列会删除目标行列上的单元格，其余单元格按规则整体平移。
- `batch_set_cell` 采用“一批坐标 + 一个统一 patch”模型：请求中 `updates` 只提供坐标，`value` / `style` 只传一份，表示对整批目标统一应用同一个 patch。
- `batch_set_cell` 的 `value` 和 `style` 至少传一个：只传 `value` 表示只改值不改样式，只传 `style` 表示只改样式不改值，同时传两者表示两者一起覆盖。
- `batch_set_cell` 带 `baseSeq`，语义与 `set_cell` 一致：`baseSeq > currentSeq` 返回 `4090`；`baseSeq < currentSeq` 时，后端会对每个目标坐标单独执行结构 transform；若中间出现 `import_sheet`，返回 `4090`。
- 结构变更成功后不会再清空用户后端 `undo/redo` 栈；后续 `undo/redo` 会结合结构 transform 继续作用于当前坐标，因此成功响应中的 `canUndo` 和 `canRedo` 以当前用户实时状态为准。
- `cursor` 是纯广播中继消息，约定前端在已 `join` 同文档后发送；后端不存储、不分配 `seq`、不写 history、不写 audit，也不校验权限和 `row/col` 合法性。

### 成功消息通用格式

```json
{
  "type": "响应类型",
  "code": 0,
  "message": "ok",
  "data": {}
}
```

### 错误消息通用格式

```json
{
  "type": "error",
  "code": 4000,
  "message": "错误描述",
  "data": null
}
```

### 业务码

| 业务码 | 含义 |
| --- | --- |
| 0 | 成功 |
| 4000 | 参数错误 / 业务规则不满足 |
| 4003 | 未 join 文档或 `clientId` 与当前 socket 身份不匹配 |
| 4004 | 文档不存在 |
| 4090 | 协同版本冲突 / OT barrier 冲突 |
| 5000 | 服务器内部错误 |

## insert_row — 插入空白行

在指定工作表的目标行之前插入一行空白行。

### 请求消息

```json
{
  "type": "insert_row",
  "docId": "doc_sys_001",
  "clientId": "user_001",
  "sheetId": "sheet_20260527_001",
  "row": 3
}
```

### 请求字段

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| type | string | 是 | 固定值 `insert_row` |
| docId | string | 是 | 文档 ID |
| clientId | string | 是 | 操作用户 ID |
| sheetId | string | 是 | 目标工作表 ID |
| row | number | 是 | 1-based 行号，允许范围 `1 <= row <= rowCount + 1` |

### 处理语义

- 在第 `row` 行之前插入一行空白行
- 所有 `cell.row >= row` 的单元格整体下移一行
- `rowCount += 1`

### 成功广播

消息类型：`row_inserted`

```json
{
  "type": "row_inserted",
  "code": 0,
  "message": "ok",
  "data": {
    "docId": "doc_sys_001",
    "clientId": "user_001",
    "sheetId": "sheet_20260527_001",
    "seq": 12,
    "row": 3,
    "canUndo": false,
    "canRedo": false
  }
}
```

### 广播字段

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| docId | string | 文档 ID |
| clientId | string | 操作用户 ID |
| sheetId | string | 实际写入的工作表 ID |
| seq | number | 本次操作的序列号 |
| row | number | 实际插入位置的 1-based 行号 |
| canUndo | boolean | 当前用户是否仍可继续 undo |
| canRedo | boolean | 当前用户是否可 redo |

## batch_set_cell — 批量改单元格

对一批目标单元格应用同一个 `value/style` patch，并作为一次原子操作生成单个 `seq`。

### 请求消息

```json
{
  "type": "batch_set_cell",
  "docId": "doc_sys_001",
  "clientId": "user_001",
  "sheetId": "sheet_20260527_001",
  "baseSeq": 16,
  "updates": [
    { "row": 2, "col": 2 },
    { "row": 2, "col": 3 },
    { "row": 3, "col": 2 }
  ],
  "value": "Batch value",
  "style": {
    "bold": true,
    "color": "#ffffff",
    "bgColor": "#2563eb"
  }
}
```

### 请求字段

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| type | string | 是 | 固定值 `batch_set_cell` |
| docId | string | 是 | 文档 ID |
| clientId | string | 是 | 操作用户 ID |
| sheetId | string | 是 | 目标工作表 ID |
| baseSeq | number | 是 | 客户端发起本次批量修改时所基于的文档版本号 |
| updates | array | 是 | 目标坐标数组，每项只包含 `row`、`col` |
| updates[].row | number | 是 | 1-based 行号 |
| updates[].col | number | 是 | 1-based 列号 |
| value | string | 否 | 批量写入的统一值；缺省时表示不改 value |
| style | object \| null | 否 | 批量写入的统一样式；缺省时表示不改 style，显式传 `null` 表示清空样式 |

### 处理语义

- `value` 与 `style` 至少传一个，否则返回 `4000`
- 若只传 `value`，则对所有目标格只覆盖 value，不影响原有 style
- 若只传 `style`，则对所有目标格只覆盖 style，不影响原有 value
- 若同时传 `value` 与 `style`，则两者一起覆盖
- 请求在单个事务内执行，整体成功或整体失败
- 整个 batch 只生成一个新的 `seq`
- 整个 batch 只写一条 history，且一次 undo/redo 会整体撤销/重做这一批变更

### OT / rebase 语义

- `baseSeq > currentSeq`：返回 `4090`
- `baseSeq === currentSeq`：直接执行
- `baseSeq < currentSeq`：读取 `baseSeq..currentSeq` 之间的 history，对 `updates` 中每个坐标单独执行结构 transform
- 参与 transform 的结构操作包括：
  - `insert_row`
  - `delete_row`
  - `insert_col`
  - `delete_col`
- 若中间出现 `import_sheet`，视为 OT barrier，返回 `4090`
- transform 后若多个旧坐标映射到同一个最终坐标，不视为冲突；后端会按最终坐标集合去重后继续执行

## cursor — 光标广播中继

将客户端光标位置直接广播给当前文档房间内的所有客户端。

### 请求消息

```json
{
  "type": "cursor",
  "docId": "doc_abc123",
  "clientId": "client_xyz",
  "row": 5,
  "col": 3
}
```

### 请求字段

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| type | string | 是 | 固定值 `cursor` |
| docId | string | 是 | 文档 ID |
| clientId | string | 是 | 当前光标所属客户端 ID |
| row | number | 是 | 当前选中单元格行号，由前端保证合法 |
| col | number | 是 | 当前选中单元格列号，由前端保证合法 |

### 处理语义

- 不存储 cursor 状态
- 不分配 `seq`
- 不写 history
- 不写 audit 日志
- 不校验权限
- 不校验 `row/col` 合法性
- 直接执行 `broadcastToRoom(docId, cursor_update)`

消息类型：`cursor_update`

```json
  }
}
```

### 广播字段

| 字段 | 类型 | 说明 |

| clientId | string | 当前光标所属客户端 ID |
| row | number | 当前选中单元格行号 |
| col | number | 当前选中单元格列号 |

## 错误消息

### 参数缺失

行操作：

```json
{
  "type": "error",
  "code": 4000,
  "message": "docId, clientId, sheetId and row are required",
  "data": null
}
```

列操作：

```json
{
  "type": "error",
  "code": 4000,
  "message": "docId, clientId, sheetId and col are required",
  "data": null
}
```

### cursor 说明

- `cursor` 消息没有单独的业务错误约束。
- 除非消息本身不是合法 JSON，或服务端出现内部异常，否则后端通常不会因为 `cursor` 请求返回专属错误。

### 工作表不存在

```json
{
  "type": "error",
  "code": 4000,
  "message": "sheet not found: sheet_missing_001",
  "data": {
    "docId": "doc_sys_001",
    "sheetId": "sheet_missing_001"
  }
}
```

### 未 join 或身份不匹配

```json
{
  "type": "error",
  "code": 4003,
  "message": "socket has not joined this document as the specified client",
  "data": null
}
```

### 协同版本冲突 / OT barrier

```json
{
  "type": "error",
  "code": 4090,
  "message": "document changed by import_sheet, please refresh and retry",
  "data": {
    "docId": "doc_sys_001",
    "baseSeq": 12,
    "currentSeq": 18,
    "conflictSeq": 15,
    "conflictOpType": "import_sheet"
  }
}
```

### 范围越界

插入行：

```json
{
  "type": "error",
  "code": 4000,
  "message": "row must be between 1 and 101",
  "data": {
    "docId": "doc_sys_001",
    "sheetId": "sheet_20260527_001",
```
