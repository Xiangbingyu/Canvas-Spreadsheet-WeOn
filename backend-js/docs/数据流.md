# 数据流

1. 文档列表页。点击【打开】\- navigate 路由跳转至表格页 \- 挂载 `SpreadsheetPage` 组件 \- 分配 `userId`【若 `localStorage` 有 id，直接用】 \- 解析 url `docId`，请求 `GET /docs/:docId` \- `const doc = await API.getDoc(routeDocId)`，当前 `doc.snapshot` 已经是 **workbook 结构** \- 更新 `workbookStore`，存所有 sheet；更新 `worksheetStore`，切到 `activeSheetId` 对应 sheet；`setDocSession` 保存 `docId` 和 `userId` \- 挂载 `SpreadsheetWorkspace` \- 从 redux 拿 `docId` 和 `userId` 发起 `join`；Canvas 从当前 `worksheetStore` 重绘

2. 分享协作链接进入。点击【链接】 \- 路由判断，挂载SpreadsheetPage组件 \- 其余与上述相同1

3. 文档列表页。点击【新建空白文档】 \- `POST /docs` 请求【当前支持 `eventId` 幂等】 \- 服务端返回默认 workbook（包含 1 个空白 `Sheet1`） \- navigate 路由跳转至表格页 \- 后续同 1

4. 表格页。点击【新建空白文档】 \- `POST /docs` 请求【当前支持 `eventId` 幂等】 \- navigate 路由跳转【同路由下，触发组件重渲染】 \- 解析 url `docId` \- `routeDocId` 变化后执行 `useEffect` 副作用，重新请求 `GET /docs/:docId` \- 之后同 1

5. 导入 Excel 表【当前按整份 workbook 导入】\- 前端解析 Excel，生成 workbook 结构 \- 必须已先 `join` 当前文档，再发起 `import_sheet` WebSocket 请求 \- 服务端整体更新文档 workbook 快照，追加 `history`，并清空当前用户的 `undoStack/redoStack` \- 先 `reply` 一条 `sheet_imported` 给发送方，再向房间广播同一条消息，因此发送方会收到 2 条相同消息 \- 前端据返回的 workbook 更新 `workbookStore` 和当前 `worksheetStore`

6. 编辑单元格。前端基于当前激活 tab 显式带上 `sheetId`，发送 `set_cell` \- 服务端按 `sheetId + row + col` 修改目标 sheet \- 先 `reply` 一条 `cell_updated` 给发送方，再向房间广播同一条消息，因此发送方会收到 2 条相同消息 \- 前端据 `sheetId` 更新对应 sheet，不依赖全局 `activeSheetId` 推断

7. 新增工作表。前端发起 `add_sheet` WebSocket 请求，显式携带 `docId`、`clientId`，可选带 `sheetName` \- 服务端生成新的 `sheetId`，创建空白 sheet，追加到 `sheetOrder`，并将 `activeSheetId` 切到新 sheet \- 先 `reply` 一条 `sheet_added` 给发送方，再向房间广播同一条消息，因此发送方会收到 2 条相同消息 \- 当前 `add_sheet` 会写入 `history`，但不会进入用户 `undoStack/redoStack`，同时也不会清空当前用户已有的 `undo/redo` 栈 \- 前端把新 `sheet` 写入 `workbookStore`，并切换当前 `worksheetStore`

8. 行列插删。前端发起 `insert_row / delete_row / insert_col / delete_col` WebSocket 请求，显式携带 `docId`、`clientId`、`sheetId` 和目标 `row/col` \- 服务端在目标 sheet 上执行结构变更，推进全局 `seq`，写入 `history` \- 先 `reply` 成功消息给发送方，再向房间广播同一条消息，因此发送方会收到 2 条相同消息 \- 结构变更成功后不会再清空用户后端 `undo/redo` 栈，后续 `undo/redo` 会结合结构 transform 继续作用于当前坐标

9. 批量改单元格。前端发起 `batch_set_cell` WebSocket 请求，显式携带 `docId`、`clientId`、`sheetId`、`baseSeq`、`updates` 和统一 `value/style` patch \- 服务端对每个目标坐标按结构历史执行 transform，必要时去重后整体写入，并只生成 1 个新的 `seq` \- 先 `reply` 一条 `batch_cell_updated` 给发送方，再向房间广播同一条消息，因此发送方会收到 2 条相同消息 \- 前端按返回的最终 `updates` 列表更新对应 sheet

10. 光标广播。前端在已 `join` 同文档后发送 `cursor` 消息，携带 `docId`、`clientId`、`row`、`col` \- 服务端仅做光标广播中继，不分配 `seq`、不写 `history`、不写 `audit` \- 房间内客户端据 `cursor_update` 更新协作者光标显示




**工作薄结构**

```JSON
{
  "activeSheetId": "sheet_20260527_001",
  "sheetOrder": ["sheet_20260527_001", "sheet_20260527_002"],
  "sheets": {
    "sheet_20260527_001": { /* worksheet snapshot */ },
    "sheet_20260527_002": { /* worksheet snapshot */ }
  }
}
```

说明：

- `activeSheetId` 表示当前文档默认激活的工作表，不代表每个用户各自实时正在查看的 tab
- `sheetOrder` 表示工作表顺序
- `sheets` 是以 `sheetId` 为 key 的工作表字典

### POST /docs — 创建文档

请求支持可选 `snapshot`：

- 不传时仍创建默认空白 workbook
- 传入时基于导入的 workbook 快照创建文档和 sheets

响应 `data`（外层不变，只改 snapshot）

```JSON
"snapshot": {
  "activeSheetId": "sheet_doc_001_001",
  "sheetOrder": ["sheet_doc_001_001"],
  "sheets": {
    "sheet_doc_001_001": {
      "id": "sheet_doc_001_001",
      "name": "Sheet1",
      "defaultRowHeight": 25,
      "defaultColWidth": 100,
      "rowCount": 0,
      "colCount": 0,
      "styles": {},
      "cells": {}
    }
  }
}
```

### set\_cell — 更新单元格

请求（新增 `sheetId`）。

说明：

- 前端应显式传当前编辑目标的 `sheetId`
- 后端当前已收紧为：`set_cell` 必须显式传 `sheetId`
- 如果 `sheetId` 不存在，服务端返回参数错误
- 若发送方未先 `join` 当前文档，返回 `4003`



```JSON
{
  "type": "set_cell",
  "docId": "doc_sys_001",
  "clientId": "user_001",
  "sheetId": "sheet_20260527_001",
  "row": 1,
  "col": 1,
  "value": "hello"
}
```

响应 cell\_updated（reply \+ broadcast，新增 sheetId）

```JSON
{
  "type": "cell_updated",
  "code": 0,
  "message": "ok",
  "data": {
    "docId": "doc_sys_001",
    "clientId": "user_001",
    "sheetId": "sheet_20260527_001",
    "row": 1,
    "col": 1,
    "value": "hello",
    "style": null,
    "seq": 13,
    "canUndo": true,
    "canRedo": false
  }
}
```

### `add_sheet` — 新建工作表

```JSON
{
  "type": "add_sheet",
  "docId": "doc_sys_001",
  "clientId": "user_001",
  "sheetName": "销售明细"
}
```

响应 — `sheet\_added`（reply \+ broadcast）

```JSON
{
  "type": "sheet_added",
  "code": 0,
  "message": "ok",
  "data": {
    "docId": "doc_sys_001",
    "clientId": "user_001",
    "seq": 15,
    "activeSheetId": "sheet_doc_sys_001_004",
    "sheet": {
      "id": "sheet_doc_sys_001_004",
      "name": "销售明细",
      "defaultRowHeight": 25,
      "defaultColWidth": 100,
      "rowCount": 0,
      "colCount": 0,
      "styles": {},
      "cells": {}
    },
    "sheetOrder": [
      "sheet_20260527_001",
      "sheet_20260527_002",
      "sheet_20260527_003",
      "sheet_doc_sys_001_004"
    ]
  }
}
```

说明：

- `sheetId` 由服务端生成，当前默认采用 `sheet_${docId}_序号` 形式
- `add_sheet` 成功后会把 `activeSheetId` 切到新建的 sheet
- 当前 `add_sheet` 会写入 `history`，但不会进入用户 `undoStack/redoStack`
- 结构变更相关操作成功后不会再清空用户后端 `undo/redo` 栈
