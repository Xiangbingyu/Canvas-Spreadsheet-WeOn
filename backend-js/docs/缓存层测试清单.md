# 缓存层测试清单

## 1. 文档目标

本文档用于整理当前缓存层改造后的测试口径，覆盖以下目标：

- 验证 `memory/mysql/redis` 三条主链路都可运行
- 验证 `GET /docs/:docId` 的快照缓存具备命中、失效、回源能力
- 验证 `GET /docs` 的列表缓存具备命中、失效、跨实例一致性能力
- 验证 `Redis` 共享缓存不会破坏多实例广播与运行态链路

## 2. 当前缓存层范围

当前第一批缓存层包含以下对象：

- `doc snapshot`
- `doc meta`
- `user docs list`

当前 key 规范见代码：

- `cache/cacheKeys.js`

当前缓存实现见代码：

- `cache/cacheStore.js`
- `cache/docSnapshotCache.js`
- `cache/docMetaCache.js`
- `cache/userDocsListCache.js`

## 3. 回归矩阵

### 3.1 原链路

环境：

- `STORE_DRIVER=memory`
- `CACHE_DRIVER=memory`
- `RUNTIME_STATE_DRIVER=memory`
- `COLLAB_BROADCAST_DRIVER=memory`

命令：

```bash
node --test tests/docs.test.js
node --test --test-concurrency=1 tests/ws.test.js
```

验证目标：

- 原单机内存链路未被破坏
- `GET /docs/:docId` 与 `GET /docs` 的缓存逻辑在 `memory` 驱动下可用
- 现有 `join/set_cell/set_title/import_sheet/undo/redo` 主流程未受缓存改造影响

### 3.2 持久化单实例链路

环境：

- `STORE_DRIVER=mysql`
- `CACHE_DRIVER=memory`
- `RUNTIME_STATE_DRIVER=memory`
- `COLLAB_BROADCAST_DRIVER=memory`

命令：

```bash
node --env-file=.env --test tests/docs.test.js
node --env-file=.env --test --test-concurrency=1 tests/ws.test.js
```

验证目标：

- `MySQL` 持久化链路正常
- 写后缓存失效不会破坏 `docs/ws` 主链路
- `doc.current_seq/history/user_op_state` 与缓存行为不冲突

### 3.3 共享缓存与多实例链路

环境：

- `STORE_DRIVER=mysql`
- `CACHE_DRIVER=redis`
- `RUNTIME_STATE_DRIVER=redis`
- `COLLAB_BROADCAST_DRIVER=redis`

命令：

```bash
node --env-file=.env --test --test-concurrency=1 tests/cacheRedis.test.js
node --env-file=.env --test --test-concurrency=1 tests/multiInstanceBroadcast.test.js
```

验证目标：

- `Redis` 共享缓存正常
- 多实例 `Redis Pub/Sub` 广播正常
- 多实例运行态索引正常
- 写后失效后，跨实例不会继续读到旧缓存

## 4. 详细测试口径

### 4.1 `doc snapshot`

覆盖文件：

- `tests/docs.test.js`
- `tests/cacheRedis.test.js`

当前已验证：

- 首次读取 miss 时可回源 `store`
- 回源后可回填缓存
- 再次读取可命中缓存
- `set_title` 后跨实例读取到新标题
- `set_cell` 后跨实例读取到新单元格值
- `undo` 后跨实例读取到撤销后的快照
- `redo` 后跨实例读取到重做后的快照
- `import_sheet` 后跨实例读取到新的导入快照
- `import_sheet` 后旧单元格不会残留在快照中

### 4.2 `user docs list`

覆盖文件：

- `tests/docs.test.js`
- `tests/cacheRedis.test.js`

当前已验证：

- 列表首次读取 miss 回源
- 列表再次读取命中缓存
- `POST /docs` 后创建者 `scope=created` 列表缓存失效
- `set_title` 后创建者 `scope=created` 列表缓存失效
- `set_title` 后参与者 `scope=participated` 列表缓存失效
- `set_title` 后参与者 `scope=all` 列表缓存失效
- `import_sheet` 后参与者 `scope=participated` 列表缓存失效
- `import_sheet` 后参与者 `scope=all` 列表缓存失效
- `import_sheet` 通过 `currentSeq` 变化验证不是读到旧列表缓存

### 4.3 `presence` 与运行态

覆盖文件：

- `tests/ws.test.js`
- `tests/multiInstanceBroadcast.test.js`

当前已验证：

- `join/leave` 后 `presence` 结果保持正确
- 多实例下 `presence` 保持一致
- 同一 `clientId` 跨实例多连接 fully-offline 判断正确

说明：

- 当前 `presence` 仍以运行态即时组装为主
- 第一批未引入 `presence` 结果缓存

## 6. 推荐执行顺序

每次缓存层有改动后，建议按以下顺序执行：

1. 先跑 `memory + memory`
2. 再跑 `mysql + memory`
3. 最后跑 `mysql + redis`

推荐命令：

```bash
$env:STORE_DRIVER='memory'; $env:CACHE_DRIVER='memory'; $env:RUNTIME_STATE_DRIVER='memory'; $env:COLLAB_BROADCAST_DRIVER='memory'; node --test tests/docs.test.js
$env:STORE_DRIVER='memory'; $env:CACHE_DRIVER='memory'; $env:RUNTIME_STATE_DRIVER='memory'; $env:COLLAB_BROADCAST_DRIVER='memory'; node --test --test-concurrency=1 tests/ws.test.js

$env:STORE_DRIVER='mysql'; $env:CACHE_DRIVER='memory'; $env:RUNTIME_STATE_DRIVER='memory'; $env:COLLAB_BROADCAST_DRIVER='memory'; node --env-file=.env --test tests/docs.test.js
$env:STORE_DRIVER='mysql'; $env:CACHE_DRIVER='memory'; $env:RUNTIME_STATE_DRIVER='memory'; $env:COLLAB_BROADCAST_DRIVER='memory'; node --env-file=.env --test --test-concurrency=1 tests/ws.test.js

node --env-file=.env --test --test-concurrency=1 tests/cacheRedis.test.js
node --env-file=.env --test --test-concurrency=1 tests/multiInstanceBroadcast.test.js
```

## 7. 通过标准

当前缓存层回归通过，至少应满足：

- `memory` 原链路通过
- `mysql` 单实例链路通过
- `mysql + redis(cache/runtime/broadcast)` 链路通过
- `GET /docs/:docId` 不会读到旧快照
- `GET /docs` 不会读到旧列表
- 参与者列表失效在多实例下成立
- `presence` 与跨实例广播未被缓存层改造破坏
